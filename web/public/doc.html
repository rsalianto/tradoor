Frost Script

tradoor's own language for indicators: a few readable lines that work out a value on every bar and draw it — on the chart or in a pane of its own — with settings, signals and the same numbers as the built-in indicators.

A script reads the chart's candles and gives back lines, levels and marks. That is all it can do: it has no word for the network, your account, your browser or the page, so a script someone else wrote can draw wrong lines at worst, and nothing more. See Safety.

Every built-in indicator that can be written in Frost Script shows its own source: open its settings and the Source tab. They are the best place to start.

Your first script

  1. On a chart, open Add an indicator and press New Frost Script. Writing a script needs you signed in with Telegram.
  2. The editor opens on a small script. Change it, or start from one of the examples on the left.
  3. Under the text it says ✓ Checks, or which line and column a mistake is on — click the message to go there.
  4. Save and add to chart. The script is now one of your indicators, in the picker under Frost Script, with its own settings, style and source.
// A moving average, and a mark where price crosses above it
input length = 20 min 2 max 500 "Length"
average = ema(close, length)
plot(average, "Average", blue)
mark(crossover(close, average), "Up", below, green)

How a script runs

The script is worked out once for every bar on the chart, from the oldest to the newest, top to bottom. On each bar, close is that bar's close, a variable holds what it was set to on that bar, and plot puts that bar's point on the line.

  • It runs over the chart's closed bars, as the built-in indicators do, and again as each new bar closes. The bar still forming is not part of it.
  • It runs in your browser, in tradoor's own engine for Frost Script. Nothing of it runs on the server.

Writing it down

  • One statement a line. ; also ends one, so two may share a line.
  • // starts a note, to the end of the line.
  • Numbers are written 14, 2.5, .5. Text goes in double quotes, and only in titles and labels: "RSI".
  • Names are letters, digits and _, starting with a letter or _, up to 40 long. Capitals count: Length is not length.
  • These words belong to the language: input state if else for to and or not pane na true false. So do the bar values, function names and colour names below — a variable cannot take them.

Settings

input length = 14 min 2 max 500 "Length"
input mult = 2 min 0.1 max 10 step 0.1 "Multiplier"
  • input name = default, then any of min, max, step and a label in quotes. The label is what the settings dialog shows; without one it shows the name.
  • A setting is the same on every bar. Use it anywhere a number goes, and as a length.
  • A setting takes whole numbers when its default is whole and its step, if it has one, is whole too. Otherwise it moves by its step, 0.1 if none is given.
  • The default must be between min and max. A value typed in the settings is kept to that range.
  • Up to 16 settings. They go at the top level, not inside if or for.

Variables and state

range = high - low                 // set on every bar
state count = 0                    // starts at 0 on the first bar…
count = count + 1                  // …and keeps its value from bar to bar
  • name = value sets a variable for this bar. A plain variable starts every bar with no value, until a line sets it.
  • state name = start starts once, on the first bar, and keeps its value from one bar to the next: a running total, a trend, a stop that trails. Its start is a plain value — a number, a setting, na — not a function over bars.
  • A variable may be set again lower down, or inside if and for; it holds the last value set.
  • A variable can be read before the line that sets it, as average[1] in its own definition.

Looking back: x[n]

gap = open - close[1]              // from the close a bar ago
rising = close > close[1] and close[1] > close[2]
  • x[n] is what x ended bar n bars ago on. x[0] is x now.
  • It works on variables and on the bar values: close[1], high[i] in a loop.
  • n is from 0 to 5,000, and can be worked out: close[length], low[i]. Before the first bar there is no value.
  • A setting has no past: it is the same on every bar.

Arithmetic and logic

WriteMeans
+ - * / %Add, subtract, multiply, divide, remainder. -x turns the sign.
== != < <= > >=Compare: 1 when true, 0 when not.
and or notLogic. Any number other than 0 is true; 0 and na are not.
c ? a : ba where c is true, else b.
( )First. Then -x; then * / %; then + -; then comparisons; then not, and, or; then ? :.

No value: na

A value can be missing: an average before it has enough bars, close[1] on the first bar, a division by zero. Frost Script calls it na, and a line simply has a gap where its value is na.

  • Arithmetic with na gives na; so does a division by zero.
  • A comparison with na is not true, so an if on it does not run.
  • max(na, 0) is na, not 0: no value in, no value out.
  • isna(x) asks; nz(x) gives 0 for na, nz(x, y) gives y.

if and for

input length = 10 min 1 max 100
if close > open {
  colour = 1
} else if close < open {
  colour = -1
} else {
  colour = 0
}

total = 0
for i = 0 to length - 1 {
  total = total + volume[i]
}
  • Blocks go in braces. else may start the line after the closing brace.
  • for i = a to b counts up from a to b, both included; if b is below a it does not run. One loop goes round 1,000 times at most.
  • Inside if and for: setting variables, maths, x[n], more if and for. Not there: drawing, settings, state, pane, and the functions over bars below.

Functions over bars

These remember the bars before: an average needs the last length values. So each one is worked out on every bar, which is why they go outside if and for — and why both sides of c ? a : b are always worked out. A length is from 1 to 5,000: a number, a setting, or sums and products of them such as length * 2, rounded to a whole number. It cannot be a variable, or what a function gives.

FunctionGives
sma(x, length)Simple average of the last length values.
ema(x, length)Exponential average: starts at the simple average of the first length, then weighs each new value 2 / (length + 1).
rma(x, length)Wilder's average, weight 1 / length, as RSI and ATR use.
stdev(x, length)Standard deviation of the last length values (of the whole set, ÷ length), as Bollinger Bands use.
highest(x, length)The highest of the last length values.
lowest(x, length)The lowest of them.
sum(x, length)Their sum.
rsi(x, length)Relative Strength Index of x, 0 to 100.
atr(length)Average true range: rma(tr, length).
change(x), change(x, n)x − x[1], or x − x[n].
crossover(a, b)True on the bar a goes from at or below b to above it.
crossunder(a, b)True on the bar a goes from at or above b to below it.
barssince(c)Bars since c was last true: 0 on that bar. na until it first is.
valuewhen(c, x)x as it was the last time c was true.
changed(x)True on a bar where x is not what it was a bar ago: changed(week), changed(trend).

An average that meets na starts over after it, as the built-in indicators do.

Maths

These work out a value from what they are given, and go anywhere.

FunctionGives

pow(x, y)x to the power y.
round(x), round(x, digits)To the nearest whole number, or to 0–10 decimals.

Drawing

Drawing goes at the top level and draws on every bar. A script draws up to 16 lines (plots, histograms and levels together), 8 fills and 8 marks. Each line needs a title of its own; it is what the legend and the Style tab show.

WriteDraws
plot(value, "Title", colour, width)A line through each bar's value, with gaps where it is na. Colour and width (0.5 to 6, else 1.5) may be left out.
histogram(value, "Title", colour)A bar from zero for each value. With no colour, above zero and below take the chart's up and down colours.
hline(value, "Title", colour)A dashed level, as hline(70, "Upper"). Gray unless another colour is given.
fill("Upper", "Lower", colour)Shades between two lines drawn above it, named by their titles.
mark(condition, "Text", above or below, colour)A mark at the bar where the condition is true: below its low (green unless named) or above its high (red unless named). Text up to 12 characters.
pane ownDraws the script in a pane of its own below the chart, with its own scale. pane price, the default, draws on the price chart.
To colour a line by a condition, draw it twice, each with na where it should not show — as SuperTrend draws its long and short stops. Every line's colour, width and style can also be changed in the indicator's Style tab.

Colours

green lime red orange yellow blue
aqua teal purple pink white gray

A line with no colour takes the next of blue, orange, purple, aqua, red, green, yellow and pink.

Examples

RSI, as tradoor works it out

pane own
input length = 14 min 2 max 1000 "Length"
move = change(close)
gain = rma(max(move, 0), length)
loss = rma(max(-move, 0), length)
strength = loss == 0 ? 100 : gain == 0 ? 0 : 100 - 100 / (1 + gain / loss)
plot(strength, "RSI", purple)
hline(80, "Upper", gray)
hline(20, "Lower", gray)

SuperTrend, with a mark at each turn

input length = 10 min 1 max 1000 "ATR length"
input mult = 3 min 0.1 max 10 step 0.1 "Multiplier"
band = mult * atr(length)
state trend = 1
state stop = na
if trend == 1 {
  stop = isna(stop) ? hl2 - band : max(hl2 - band, stop)
  if close < stop {
    trend = -1
    stop = hl2 + band
  }
} else {
  stop = isna(stop) ? hl2 + band : min(hl2 + band, stop)
  if close > stop {
    trend = 1
    stop = hl2 - band
  }
}
turned = changed(trend)
plot(trend == 1 ? stop : na, "Long stop", green)
plot(trend == -1 ? stop : na, "Short stop", red)
mark(turned and trend == 1, "Buy", below, green)
mark(turned and trend == -1, "Sell", above, red)

Volume well above its average

pane own
input length = 20 min 2 max 500 "Average of"
input times = 2 min 1 max 10 step 0.1 "Times the average"
usual = sma(volume, length)
histogram(volume, "Volume")
plot(usual * times, "Spike line", orange)
mark(volume > usual * times, "Spike", above, orange)

Every built-in indicator that is written in Frost Script — SMA, EMA, Bollinger Bands, Keltner Channels, RSI, Stochastic RSI, MACD, ATR, VWAP — is in the editor's examples and in its own Source tab, and gives exactly the numbers the built-in does.

From Pine Script, with an AI

An indicator written in TradingView's Pine Script v6 can be turned into Frost Script by an AI chat — Claude, ChatGPT, Gemini or another. The instructions below teach it the whole language and how each part of Pine Script maps onto it, or why it cannot.

  1. Copy the instructions: the button below, or Pine Script → Frost: copy AI instructions in the Frost Script editor.
  2. Paste them into the AI chat, and then the Pine Script v6 source of the indicator.
  3. Paste the script it answers with into the editor. It is checked at once: if a line is wrong, give the AI the message and the line, and ask it to put it right.
  4. Before you rely on it, put it on a chart beside the original and compare the numbers on a few bars.

Mistakes and messages

A script is checked as it is typed. A mistake says its line and column and what is wrong, and the line's number turns red. Some you will meet:

MessageWhat to do
foo is not known hereA name not set anywhere, or spelt differently (capitals count).
ema(value, length)The function takes other arguments: here a value and a length.
a length is a number or a settingA length cannot change from bar to bar: use a number or an input.
… call it outside if and forA function over bars, or drawing, inside a block. Work the value out above the block, and use it inside.
close is built inA variable with a name the language uses: pick another.
name it, as x = …A line that works out a value and keeps it nowhere.
two lines are called "A"Give each line its own title.
this script takes too long to work outLoops that together ask too much: fewer, or shorter. See Limits.

A script that runs into a problem on the chart says so in the chart's legend, beside its name.

Safety

Frost Script is safe by what it is, not by what it forbids. A script is read and worked out by tradoor's own engine for it, written in Rust. It is never turned into JavaScript or any other code a browser runs.

  • Nothing to reach. The language has no word for the network, storage, your account, your browser, the page or the clock. In the browser it runs in a module that imports nothing at all: it is given candles and gives back numbers.
  • It always ends. Every limit is held, so a script cannot freeze a chart.
  • Checked twice. The server checks a script with the same engine when it is saved; your browser checks it again before it runs.
  • Text is text. Titles, labels and mark text are shown as plain text, never as page code.
  • Moderated. Scripts are looked after by tradoor's moderator, who can remove one that misleads. A removed script runs for no one, its author is told why, and it can be restored.
A script can still be wrong. It cannot harm you, but a script can draw a line that misleads. Read a script before you trade on it, and remember that no indicator knows where price goes next.

Your scripts and your account

  • Writing and keeping scripts needs you signed in with Telegram: Settings, Account. Signed out, you can read the examples and every built-in's source.
  • Your scripts are kept on tradoor's server with your account, so they follow you to every device you sign in on. Up to 100.
  • A script on a chart is part of that chart's layout, with its settings and style, like any indicator.
  • Deleting a script takes it off the charts of the layout you are in, and it draws on no chart anywhere after.
  • A script the moderator removed shows in your list with the reason. It runs for no one and cannot be changed, but you can still read and delete it.

Public scripts and the Community

The indicator picker has three tabs: Built-in, tradoor's own; Community, the scripts their authors made public; and My scripts. One search runs through all three, and each tab says how many it matches.

  • A script is private until you make it public: yours alone, on your charts.
  • Set it to Public beside its name in the editor, write its description — what it shows, and how to read it, in 30 characters at least — and save. It is listed in the Community under your username, for anyone to add to a chart, signed in or not, and the chart's legend shows it beside the script's name. A public script must check.
  • Every public script is on the Community showcase, a page of its own with a link for each to share. Its chart there is drawn live by tradoor's engine, on the market and timeframe of the chart you shared it from, with your settings: open the editor from that chart before you save. No picture is kept.
  • Your username is yours to choose, in place of your Telegram name, so you can stay anonymous: Settings, Account, or the editor the first time you share. It is 3 to 20 letters a to z, digits and _, starting with a letter, and one no one else has. You choose it once: it can never be changed, and stays with your Telegram account, so a name on a script always means the same author.
  • A change you save to a public script reaches every chart it is on.
  • Set it back to Private, or delete it, and it leaves the Community and draws on no one else's chart.
  • On a Community script, Copy opens a copy of your own in the editor, to read or to change. Its Source tab shows its text on the chart, too.
  • The moderator can remove a public script that misleads: it then runs for no one, and its author is told why.
Read a script before you trade on it. A Community script is someone else's work. It cannot reach your account or your browser, but it can draw a line that misleads.
